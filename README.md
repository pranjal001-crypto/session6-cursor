# Prompt Engineering Session 06: Classwork (CW)

## Overview
This directory contains the classwork deliverables for Session 06. The primary focus of this lab was to explore AI-assisted development using the **Cursor AI editor**, specifically focusing on safe code refactoring, output verification, and configuring persistent AI rules.

## Objectives Achieved
1. **AI Mode Exploration:** Differentiated between Cursor's "Understand-only" (Chat) mode for logic analysis and "Inline Edit" mode for rapid code generation and refactoring.
2. **Code Refactoring:** Cleaned up a poorly written Python script (`messy_report.py`) by utilizing AI to implement descriptive naming, f-strings, and reusable functions without altering the core functionality.
3. **Strict Output Verification:** Ensured the refactored code output matched the original baseline script character-for-character to guarantee system stability.
4. **Custom AI Rules:** Created and enforced custom Python coding standards using Cursor's `.mdc` rule engine, successfully verifying that the AI adhered to these rules when generating new features.

## Repository Contents

### Source Code
* **`messy_report.py`**: The original, unoptimized baseline script provided for the lab.
* **`refactored_script.py`**: The fully refactored, clean version of the script utilizing Python best practices.

### Documentation & Evidence
* **`original_output.txt`**: The baseline terminal output generated by the messy script, used as the control reference.
* **`verification_note.txt`**: A confirmation document verifying that the refactored script's output identically matches the original output.
* **`ai_modes_observation.txt`**: A brief analysis of when to best utilize Cursor's Chat vs. Inline Edit features.
* **`rules_comparison_table.md`**: An evidence-based table proving that Cursor AI successfully followed the project's custom rules when prompted to add new code.

### Configuration
* **`.cursor/rules/python-standards.mdc`**: The persistent Cursor rules file dictating the coding standards (e.g., forced one-line docstrings, f-strings, and descriptive variable names) for all Python files in this project.
